# MAIOS — Multi AI Operative System

Status: **demonstrated / evolving**

Public surface: https://maios.it

MAIOS is the current operational convergence of a substantial part of the work
represented in this portfolio.

It is designed around a practical problem: AI-assisted projects often lose
context, memory, decisions, competence and direction as models, tools, sessions
and environments change. MAIOS brings these elements into a project-specific
operating context rather than treating each interaction as an isolated chat.

## Operating relation

```text
person / organisation / project context
        ↓
Project Kernel
        ↓
models + tools + memory + competences + sources + state
        ↓
continued work / review / evolution
```

The Project Kernel is the project-specific operating seed. RepoKernel remains a
separate generative metakernel/source and does not become the owner of the
project it helps generate.

## Public experience

The current public MAIOS surface exposes:

- guided AI setup;
- a self-configuring project package;
- Project Kernel and component explanations;
- contextual MAIOS Chat;
- a human consulting path;
- an ecosystem/System Atlas;
- editorial guides for different user and organisation contexts.

The system therefore acts both as an operational AI surface and as an entry
point for applying the architecture to real projects.

## Demonstrated evidence

The current owner-native MAIOS state reports:

- a published self-configuring Project Kernel package;
- project-specific context and state generation;
- distinct facts, hypotheses, unknowns and possibilities;
- reviewed evolution deltas for state, memory, competence, skill/function and
  meta-evolution candidates;
- a Codex setup path that preserves owner review before completion;
- maintained reentry that reconstructs direction, verified/uncertain state and
  the next useful experiment without the original interview;
- deterministic package identity for the currently published build.

The portfolio intentionally does not use a package version number as a primary
public claim because page copy and owner-native release state can drift during
active development.

## Open validation

Current evidence does **not** justify claiming universal host support or
unbounded autonomy.

Still open in the owner-native state are broader validation across Claude Code,
OpenCode and Hermes, a non-synthetic external case, second-operating-system
reproducibility and further latency reduction.

## Research relation

MAIOS is where several longer-running research directions become operationally
composable:

- continuity across context transitions;
- operational/system awareness;
- memory and source distinction;
- competence extraction and reuse;
- reviewable evolution;
- agentic and multi-AI coordination;
- AI-native UX;
- human authority and effect boundaries.

The longer-term direction includes **autopoietic AI architectures**: systems
that can learn from operational experience and reorganise memory, competences
and functions through reviewable change. This is a research direction, not a
claim of unrestricted self-modification or independent authority.

## Relationship to earlier work

MAIOS does not erase or semantically absorb the earlier repositories.

```text

RepoKernel / Project Kernel / skills / seeds
  generative and reusable competence infrastructure

THIA
```

The portfolio uses this hierarchy so a reviewer can understand the current
system first and then inspect the evidence and genealogy underneath it.

## Boundary

- No claim of consciousness or subjective experience.
- “Awareness” means operational awareness tied to state, context, evidence,
  limits, memory and action.
- No claim of unrestricted self-modification.
- No claim that all tools, accounts, sensors, automations or services are
  active unless they are actually connected and authorised in the target
  context.
- Human review and effect authority remain distinct from generated proposals.
